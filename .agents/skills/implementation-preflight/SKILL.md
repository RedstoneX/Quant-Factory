# Implementation Preflight

Produce a short implementation boundary before editing executable behavior.
Do not implement while performing this preflight.

1. Confirm the canonical repository, accepted `main` base, branch, clean owned
   worktree, and exact owned paths.
2. Read `AGENTS.md`, current `docs/MILESTONES.md`, and only the relevant
   decisions. Identify the exact active-path step advanced or the demonstrated
   blocker removed.
3. Inspect the relevant code, tests, accepted ADRs or specifications, and
   current behavior. Verify the load-bearing current-state claim.
4. Inventory reusable project code and tests, licensed dependencies,
   owner-approved prototypes, and mature maintained legally compatible
   components. Prefer the shortest suitable reuse path. State the verified gap
   before proposing custom code.
5. Define the smallest safe change, explicit exclusions, stop conditions, and
   any dependency on owner authority. Preserve protected-data, credential,
   execution, and capital boundaries.
6. Define focused decisive validation, independent review when required, and
   separate target-environment proof for affected environment inputs.
7. Classify documentation impact under
   `docs/DOCUMENTATION_GOVERNANCE.md`; do not create a competing status or
   roadmap document.

Return: path step/blocker, evidence checked, selected reuse, remaining gap,
owned paths, exclusions, stop conditions, validation, and documentation
impact. If any boundary is unresolved, stop and report it plainly.
